<verified_facts>
These were reproduced during planning against this repo's own toolchain. Do not re-derive them,
and do not "simplify" the design on the assumption that they are not true.

1. Under `pnpm vitest run`, `new Error().stack` reports **real `.ts` paths with exact source
   line and column numbers** — vite-node's sourcemaps are already applied by the time `.stack`
   is read. Verified with a throwaway `packages/vitest/src/*.ts` module called from a
   `packages/vitest/test/*.test.ts` file: frame 0 was
   `at captureCallSite (/abs/.../packages/vitest/src/<Module>.ts:3:17)`, frame 1 was
   `at registrar (/abs/.../packages/vitest/src/<Module>.ts:7:55)`, frame 2 was
   `at /abs/.../packages/vitest/test/<file>.test.ts:6:20` — and line 6 column 20 was exactly
   where the call was written. No `--enable-source-maps` flag was needed.

2. Frames come in three observed shapes and the parser must handle all three:
   `    at fnName (/abs/path/File.ts:3:17)`, `    at /abs/path/file.test.ts:6:20` (anonymous),
   and `    at fnName (file:///abs/path/x.js:302:11)` (node_modules ESM). A fourth,
   `    at new Promise (<anonymous>)`, carries no `line:column` and must be skipped, not crashed on.

3. `Error.stackTraceLimit` defaults to 10 in this runtime. The caller's frame is always frame 2
   here, so the default is sufficient; do not mutate the global.

4. `Error.captureStackTrace` is NOT usable: it is a V8 extension typed only by `@types/node`,
   and `packages/vitest/tsconfig.json` inherits `types: []` from `tsconfig.base.json`. Plain
   `new Error().stack` IS typed (`lib.es5.d.ts` declares `Error.stack?: string`). Use the plain form.
</verified_facts>

Export exactly three values plus one type, each with an explicit return annotation

- `export type DefinitionSite = { readonly file: string; readonly line: number; readonly column: number }`
- `export const captureCallSite = (): DefinitionSite | null`

`captureCallSite` reads `new Error().stack`, returns `null` when it is `undefined`, then
`.split("\n")` and drops the first line (the `Error` header — the error carries no message, so
the header is exactly one line). Parse each remaining line with a single module-scope regex that
captures the location and the trailing line and column, tolerating all three observed frame
shapes and yielding no match for `at new Promise (<anonymous>)`. Strip a leading `file://` prefix
from every parsed location uniformly, so the comparison in the next paragraph and the rendered
output use one form.

Frame selection is by directory, never by a hard-coded frame count. Frame 0 is always
`captureCallSite` itself, so derive `selfDir` from frame 0's file by slicing up to and including
the last path separator (accept both `/` and `\`, so a Windows stack does not silently return
frame 0's own module). Return the first subsequent frame whose file does not start with
`selfDir`; return `null` if none does. This is what makes the result the author's `Given(...)`
line rather than `describeFeature.ts`'s registrar, and it keeps working when the package is
consumed from `dist/` where every internal module shares one directory.

`formatCallSite` returns the module-scope constant `an unrecorded location` for `null`, copying
`ParameterTypes.ts`'s `unrecordedLocation` string verbatim so the two packages' messages read
the same, and `${file}:${line}:${column}` otherwise.

`compareCallSites` returns a number suitable for `Array.prototype.sort`: compare `file` with
`localeCompare` first, then `line - line`, then `column - column`, all numerically for the last

`Order.combineAll` from `effect/Order` — PATTERNS.md records that it throws in this exact build

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test author's source file → `captureCallSite` | The captured path and line originate in the developer's own runtime stack, not in any network or file input. |
| `Error.prototype.stack` (V8-formatted) → the frame parser | An unstructured, engine-formatted string is parsed with a regex. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01-01 | Denial of Service | `CallSite.ts` frame regex | mitigate | The frame regex is anchored (`^`/`$`) and matches one line at a time against a stack whose length `Error.stackTraceLimit` caps at 10 frames. No nested unbounded quantifier that could backtrack catastrophically; keep the regex anchored and single-line when writing it. |
| T-06-01-02 | Tampering | frame selection by directory prefix | mitigate | Selection compares against `selfDir` derived from frame 0 at capture time rather than a hard-coded path or frame index, so a relocated or bundled module cannot silently make the capture point at this package's own line. Task 1's mutation record A is the standing proof. |
| T-06-01-03 | Information Disclosure | absolute developer paths in a later error message | accept | The captured path is an absolute path on the developer's own machine and appears only in a test-time error message printed to that developer's terminal. It is never transmitted, persisted, or included in the published tarball. Cucumber-js, vitest and every stack trace in the toolchain already expose the same information. |
| T-06-01-SC | Tampering | package-manager installs | accept | This plan installs nothing. No `pnpm add` is performed and `pnpm-lock.yaml` is not modified; `pnpm install --frozen-lockfile` must continue to succeed unchanged. |
</threat_model>
