<verified_facts>
Four constraints of `effect@4.0.0-rc.112`, already discovered and recorded at
`packages/gherkin/src/Errors.ts:15-48`, verified against the installed build. Do NOT rediscover
them and do not "simplify" past any of them:

1. `Schema.Literals([...])` — the plural, ARRAY form. The variadic `Schema.Literal(a, b, c)` THROWS when used as a `Schema.TaggedError` field in this build.
2. `Schema.Defect`, bare or wrapped in `Schema.optional`, THROWS at construction. Use `Schema.OptionFromUndefinedOr(Schema.Unknown)` for a `cause` field.
3. Every optional field is `Schema.OptionFromUndefinedOr`, so the CONSTRUCTOR requires an explicit `Option.some(x)` / `Option.none()`. Omitting the key fails construction outright — there is no implicit default.
4. NO custom constructor. `@effect/tsgo`'s `overriddenSchemaConstructor` diagnostic rejects any constructor override on a `Schema.TaggedError` subclass. Wrapping goes in a separate factory function, not in the class.

Verified during planning against the installed `@effect/vitest@4.0.0-rc.112` (`dist/index.d.ts`):
the module-level `effect` export is typed `Vitest.Tester<Scope.Scope>`, whose call signature is
`<A, E>(name: string, self: (ctx: V.TestContext) => Effect.Effect<A, E, R>, timeout?) => void`.
A `() => Effect.Effect<void, unknown, Scope.Scope>` is assignable to that `self` position.
</verified_facts>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.feature` file text and registered pattern text → `StepMatchError.message` | Author-controlled strings are embedded verbatim into an error message rendered to a developer terminal. |
| step Effect error channel → `TestApi.effect`'s `unknown` | An arbitrary user error value crosses the seam into vitest's reporter. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03-01 | Denial of Service | untruncated `message` and `matchedPatterns` | accept | Never truncating is a locked developer decision (`packages/gherkin/src/Errors.ts:50-58`, pinned byte-for-byte in `packages/gherkin/test/Contracts.test.ts`) and Task 3 asserts it. Inputs are the developer's own `.feature` file and their own step patterns, already resident in memory; a long message is a long terminal line. Adding a cap here would break a pinned contract to defend a budget that does not exist. |
| T-06-03-02 | Tampering | `Schema.TaggedError` field decoding | mitigate | Every field is declared with an explicit schema, and `Schema.OptionFromUndefinedOr` forces the constructor to receive an explicit `Option`. There is no `Schema.Any` field and no custom constructor that could bypass validation — acceptance criteria assert both by grep. |
| T-06-03-03 | Repudiation | error without a location | mitigate | `uri` is required and `line` is an explicit `Option`, so an error either names its source location or visibly says it has none. There is no silent default of `0` or `""`. |
| T-06-03-04 | Information Disclosure | `cause` carrying arbitrary values | accept | `cause` is `Option<unknown>` and is populated only by this package's own code from values already in the developer's process. Nothing serialises it off-machine. |
| T-06-03-SC | Tampering | package-manager installs | accept | This plan installs nothing. No `pnpm add` runs, `pnpm-lock.yaml` is not modified, and `pnpm install --frozen-lockfile` must continue to succeed unchanged. |
</threat_model>
