<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.feature` file text and pattern text → `console.warn` on a terminal / CI log | Author-controlled strings are written to a stream that CI systems capture, archive and sometimes render. |
| `packages/vitest` manifest and lockfile → the installed dependency tree | A dependency declaration changes what is installed. |
| `@effect-cucumber/vitest` public barrel → consumer code | Anything exported here is frozen into the published contract. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-07-01 | Tampering | ANSI/control characters in a warning written to a terminal | mitigate | The warning message is `Plan.ts`'s already-assembled string, in which every pattern and step text is quoted with `JSON.stringify` — which escapes control characters, so a pattern containing an ANSI escape or a carriage return cannot rewrite the terminal line or forge a second warning. `describeFeature` passes `warning.message` through unchanged and rebuilds nothing; mutation record B in Task 3 is the standing proof of that. |
| T-06-07-02 | Tampering | supply chain — the `@types/node` declaration | accept | No new package enters the dependency tree. `@types/node` is already pinned in `pnpm-workspace.yaml`'s default catalog at `^26.4.0` and already declared by `packages/gherkin`; this adds a second `catalog:` reference to the SAME resolved entry. An acceptance criterion asserts `pnpm-workspace.yaml` is unchanged, and `pnpm install --frozen-lockfile` succeeding against the committed lockfile is the proof that no version moved. It is declared in `devDependencies` only, so a consumer installs nothing new — `pnpm verify:pack` and `pnpm verify:no-runner-dep` both re-assert the shipped manifest's shape. |
| T-06-07-03 | Elevation of Privilege | over-exporting internal stages | mitigate | Only the two error/warning types are added to the barrel. `planFeature`, `emitFeature`, `buildScenarioEffect`, `captureCallSite`, `TestApi` and `collectFeature` stay internal, asserted by a criterion that greps the barrel for them. A published internal stage is a contract this project would have to keep, and the existing "Deliberately NOT exported" policy is what stops it. |
| T-06-07-04 | Information Disclosure | absolute definition-site paths in CI logs | accept | Already accepted at T-06-01-03 and T-06-06-04, and unchanged here: the same paths appear in every stack trace the toolchain prints. |
| T-06-07-05 | Repudiation | a Feature that silently emits nothing | mitigate | `packages/vitest/test/emission.test.ts` runs `describeFeature` for real and asserts the emitted tests execute and pass. Task 2's recorded mutation — calling `collect` but not `emitFeature` — makes that file fail, so the "collects and emits nothing" regression cannot merge quietly. |
| T-06-07-06 | Tampering | a leaked `console.warn` stub | mitigate | The stub is restored in a `finally`, and an acceptance criterion requires two consecutive `pnpm test` runs to produce identical output, which a leaked stub would break. |
</threat_model>
