<objective>
Give the hook store a way to record WHICH Rule (if any) a hook was registered under, and give the hook
runner a pure function that merges a Feature-level `HookSet` with a Rule-level one in the exact
ordering D-02 requires — outer-to-inner for the "before" gates, inner-to-outer for the "after"
guarantees.

Purpose: ADR-EC-010 makes `Before`/`After`/`BeforeStep`/`AfterStep` Rule-scopeable, but `HookRegistry.ts`
today has no scope concept at all (its own header says so, and Phase 7 deliberately did not reproduce
`Registry.ts`'s stack for it). This plan adds the minimum: a `ruleId` field on the stored definition —
never a second stack — plus a merge function whose ORDER encodes D-02 once, so no later plan has to
reconstruct the ordering rule at a call site. `groupHooks` itself does not change: partitioning stays a
pure function over whatever flat list it is handed, and scoping is handled entirely by which list that
is (08-05a filters by `ruleId` before calling it).
Output: `HookRegistry.ts`'s scope-aware store, `Hook.ts`'s `mergeHookSets`/`emptyHookSet`, both test
files extended.
</objective>
