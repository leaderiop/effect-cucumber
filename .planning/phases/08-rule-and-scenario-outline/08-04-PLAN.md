<objective>
Make every Outline row's emitted test title show every Examples column and that row's value for it —
`Applying a valid discount code (code=SAVE10, percent=10, expected=31.50)` — even when the Outline's
own title text has no `<placeholder>` for `@cucumber/gherkin`'s interpolation to substitute, and add
the regression test for the loop-variable-capture bug class (Pitfall 34) that a naive per-row emission
is prone to.

Purpose: `ParsedScenario.name` (the interpolated Pickle name) already makes two Outline rows distinct
when their title text references a placeholder — verified empirically against the installed
`@cucumber/gherkin@42.0.1` before this plan was written — but does NOT when it doesn't: the
discount-codes worked example's own title, `Applying a valid discount code`, carries no placeholder at
all, so both its rows' `Pickle.name` are byte-identical today. D-03 is a locked decision requiring the
full column=value suffix on every row regardless, for maximum `-t` filterability. This is new logic —
not a case that turns out to be free — so it lands as its own small module ahead of the Rule-wiring
plans, independent of them.
Output: `OutlineTitle.ts`'s pure title-building function, `Runner.ts` wired to use it, and a Pitfall-34
regression proof.
</objective>

  export const buildScenarioTitles: (feature: ParsedFeature) => ReadonlyMap<string, string>
    // Keyed by ParsedScenario.id (== ScenarioPlan.scenarioId == Pickle.id). Value is:
    //   - `${scenario.name}` unchanged, for a plain Scenario or an Outline row whose Examples row
    //     cannot be located (defensive fallback, never thrown)
    //   - `${scenario.name} (${col1}=${val1}, ${col2}=${val2}, ...)` for an Outline row, columns in
    //     the Examples table's own header order

NOTE ON TYPES: `packages/vitest` depends only on `@effect-cucumber/gherkin`, never directly on
`@cucumber/messages` — do not add it as a new dependency. `GherkinDocument` is already re-exported by
the gherkin package barrel; derive every nested AST shape this task needs via indexed-access types on
it, e.g. `type Feature = NonNullable<GherkinDocument["feature"]>`, `type FeatureChild =
Feature["children"][number]`, `type Rule = NonNullable<FeatureChild["rule"]>`, `type RuleChild =
Rule["children"][number]`, `type Scenario = NonNullable<FeatureChild["scenario"]>`, `type Examples =
Scenario["examples"][number]`, `type TableRow = NonNullable<Examples["tableHeader"]>`. The real
`@cucumber/messages@34.2.1` shapes these mirror exactly (verified by reading
`node_modules/@cucumber/messages/dist/messages.d.ts` — do not re-derive them from scratch): `Feature.
children: readonly FeatureChild[]`; `FeatureChild = { rule?: Rule; background?: Background; scenario?:
Scenario }`; `Rule.children: readonly RuleChild[]`; `RuleChild = { background?: Background; scenario?:
Scenario }`; `Scenario.examples: readonly Examples[]`, `Scenario.id: string`; `Examples.tableHeader?:
TableRow`, `Examples.tableBody: readonly TableRow[]`; `TableRow.cells: readonly TableCell[]`,
`TableRow.id: string`; `TableCell.value: string`.
</interfaces>

    first, and never assumed equal to it). If found, the title is `${scenario.name} (${rowInfo.header
    .map((name, i) => `${name}=${rowInfo.values[i]}`).join(", ")})`. If not found (a plain Scenario, or

    no placeholder produces byte-identical `Pickle.name` values for every row.
