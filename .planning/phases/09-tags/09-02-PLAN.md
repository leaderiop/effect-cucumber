Create `packages/vitest/src/Tags.ts` exporting exactly the surface in the `<interfaces>` block above.

`skipTag = "@skip"` and `onlyTag = "@only"` are the only two reserved tags (D-07). `onlyTag` gets a
named constant even though NOTHING branches on it, and its doc comment must say why: D-06 makes
`@only` deliberately inert — it is emitted as a plain tag and never routed to the framework's `only`
mode, because that mode fails a CI run by design. Recording the omission as a decision is
`Errors.ts` note structure's own precedent.

`isSkipped(tags)` is `tags.includes(skipTag)` — exact-string, case-sensitive matching, which is the
Cucumber tag convention. State in the comment that no case-insensitive or prefix matching was
requested and that adding one would make `@Skip` and `@skip` silently interchangeable.

`makeTagFilter` normalises the two optional public arrays into a required `TagFilter`. Both
`undefined` and `[]` mean NO FILTER — never "match nothing". Write the reason into the function's own
doc comment: a caller computing `excludeTags` from a variable that happens to be empty must get their
whole suite, not silence, and `includeTags: []` meaning "match nothing" would silently delete an
entire suite behind a green run. This mirrors `describeFeature.ts`'s `scenarioLayers` field comment,
where an absence is stated as the contract rather than left as an optimisation.

`noTagFilter` is the exported "no filter" sentinel — `{ include: [], exclude: [] }` — so
`Runner.ts`'s `emitFeature` can declare its filter argument REQUIRED and callers that filter nothing
pass a named value rather than an optional they forgot. `emptyHookSet` is the precedent.

`shouldEmit(filter, tags)` returns true when the Scenario survives BOTH halves: the include half
passes when `filter.include` is empty or the Scenario carries at least one included tag; the exclude
half passes when the Scenario carries none of the excluded tags. Exclude wins a conflict — a tag in
both arrays excludes. Use `includes`/`some` set semantics so a duplicated tag (a tag written on both
a Feature and its Scenario appears twice in `ParsedScenario.tags`) is inert.

Open the file with this package's standard module doc comment format: the "N things about this module
are not visible from the code" lettered structure used by `Runner.ts`, `TestApi.ts` and
`describeFeature.ts`. Notes to write: (a) this is a module and not a private helper in `Runner.ts`
because `spec/traceability.md` §1's row for behavior doc 02 already names it and because
`TestApi.ts`'s closing paragraph forbids a runtime value there; (b) empty means no filter; (c)
`@only` is deliberately inert; (d) this module is INTERNAL and not re-exported from
`packages/vitest/src/index.ts` — name plan 09-07 as the owner of any barrel decision, following
`Errors.ts`'s closing-paragraph convention.

No imports at all. No framework import, no `effect/*` import, no local import.
