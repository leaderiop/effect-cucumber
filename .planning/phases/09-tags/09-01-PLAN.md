Create `vitest.config.ts` at the repository root. Import `defineConfig` from `vitest/config` and
default-export `defineConfig({ test: { tags: [...], allowOnly: false } })`.

`test.tags` must declare exactly these nine entries, each as `{ name: "…" }`:
`@skip`, `@only`, `@slow`, `@wip`, `@featuretag`, `@ruletag`, `@scenariotag`, `@exampletag`.
(That is eight; the ninth slot is deliberately empty — see below.)

Write these facts into the file as comments, because none of them is visible from the code:

(a) `strictTags` is deliberately left at its default `true`. RESEARCH Finding 1 verified the default
    empirically against vitest 4.1.11 (`strictTags: config.strictTags ?? true`) — a typo'd tag in a
    fixture must fail loudly here, which is exactly what a consumer gets too. Setting it to `false`
    is not a fix: RESEARCH Finding 2 verified that `--tagsFilter` validates against `test.tags`
    regardless of `strictTags`, so `strictTags: false` silences the test side and leaves the filter
    side broken.

(b) `allowOnly: false` is set so every LOCAL run behaves like CI. vitest's own default is
    `allowOnly: !isCI`, so without this line roadmap success criterion 3 would hold in GitHub
    Actions and be unverifiable locally. The accepted cost: a developer using `.only` locally must
    pass `--allowOnly`.

(c) `include` and `exclude` are deliberately ABSENT. Setting either is the likeliest way to silently
    stop running some package's tests; omitting them preserves the defaults every existing test file
    in this repo relies on.

(d) `@undeclared-on-purpose` is RESERVED and must NEVER be added to the list above. Plan 09-06 emits
    it from `packages/vitest/test/emission.test.ts` to prove the D-08 catch-and-degrade path: the
    Scenario still runs untagged and a located warning prints, instead of the file collecting zero
    tests. Declaring it deletes that test's meaning while leaving it green.

(e) `@skip` and `@only` are the library's two reserved tags (D-05, D-06); the rest are probes used by
    this repo's own suite. A future phase that adds `@REQ-EC-NNN` acceptance tags (AGENTS.md §5) adds
    them here or reaches the D-08 degradation path.

Then verify RESEARCH assumption A5 empirically: capture `pnpm test`'s reported "Test Files" and
"Tests" counts BEFORE creating the file and again AFTER, and record both numbers verbatim in the
plan summary. They must be identical.

Run `pnpm lint` afterwards — the new file is covered by `dprint check` and `oxlint`, and this repo
formats with no semicolons, double quotes, 120 columns, never trailing commas. Use `pnpm lint-fix`
