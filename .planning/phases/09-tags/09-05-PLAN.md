emission carries no tags, so if it throws too, the original failure was not about tags. In that case
re-throw the ORIGINAL caught value rather than swallowing it or replacing it. Write that reasoning
into the factory's doc comment.

Order within the catch matters and must be stated: re-emit first, then warn. A throw from the warning
path must not be able to leave the Scenario unregistered.

runner, so a CLI tag filter cannot select it — which is why the warning names the tag and points at
