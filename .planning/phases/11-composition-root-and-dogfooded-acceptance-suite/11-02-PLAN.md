## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shared `Database` Layer -> every Scenario in the Feature | State written by one Scenario is reachable by the next unless the Background clears it. |
| `.feature` tag text -> runner tag validator | An undeclared tag degrades or zeroes the file. |
| `TestClock` -> Scenario boundary | A clock adjustment leaking across Scenarios is the exact defect ADR-EC-018 exists to prevent. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-02-01 | Tampering | shared `Database` state across Scenarios | medium | mitigate | The Background's `Given the database is empty` calls `Database.clear` per Scenario, which is why `clear` exists on the service at all. Asserted by `Then the database has 1 user` reading a count that would be 2 if the previous Scenario leaked. |
| T-11-02-02 | Information disclosure | `TestClock` leaking across Scenarios on the shared path | high | mitigate | The zero-reading partner Scenario asserts the clock still starts at 0 after the previous Scenario advanced it by an hour. Mutation C records that swapping their order does not change the result. |
| T-11-02-03 | Denial of service | an undeclared tag collapsing the file to zero tests | high | mitigate | The collected-count acceptance criterion (at least 5 passing, exactly 1 skipped) fails when the file collects nothing; mutation D records the observed degradation path. |
| T-11-02-04 | Spoofing | a `@REQ-EC-NNN` Scenario asserting nothing load-bearing | high | mitigate | PROH-11-01 plus the criterion that the `@REQ-EC-021` step asserts a value computed through the library rather than a constant. |
