<task type="auto">
  <name>Task 1: Write scripts/verify-pack.sh and wire the packaging checks</name>
  <files>scripts/verify-pack.sh, package.json, pnpm-lock.yaml</files>
  <action>
Install: `pnpm add -Dw publint@0.3.24 madge@8.0.0`

Add root scripts:
```jsonc
"circular": "madge --circular --extensions ts packages/*/src",
"verify:pack": "bash scripts/verify-pack.sh"
```

Write `scripts/verify-pack.sh` (`set -euo pipefail`, `chmod +x`). It must build
first (`pnpm build`), then for **each** of `@effect-cucumber/gherkin` and
`@effect-cucumber/vitest`:

1. Pack into a temp dir:
   `pnpm --filter <name> pack --pack-destination "$TMP"`
2. Extract it (`tar -xzf` into `$TMP/<name>`), giving `package/package.json` and
   the full file list.
3. Assert, using `node -e` for the JSON (do **not** depend on `jq` — it may not
   be installed):
   - `exports["."]` ends with `dist/index.js` — the `publishConfig.exports`
     swap fired. If it still points at `src/`, fail with
     "publishConfig.exports did not apply".
   - No `main` and no `types` field.
   - No `require` condition anywhere in the `exports` map, and `tar -tzf` lists
     zero `.cjs` files — fail with "ESM-only violated" otherwise.
   - `dist/index.js` and `dist/index.d.ts` are both present in the tarball.
   - The `README.md` is present in the tarball.
   - No dependency/peerDependency/devDependency value anywhere in the packed
     manifest still contains the literal string `catalog:` or `workspace:` —
     fail with "unexpanded protocol in published manifest".
4. For `@effect-cucumber/vitest` only, the Pitfall 20 guard:
   - `peerDependencies.effect` must **not** match `^[0-9]` (a bare exact
     version). Fail with a message that names Pitfall 20 explicitly:
     "peerDependencies.effect is an exact pin (<value>) — Pitfall 20: the
     catalog expanded a pin into the published peer range; consumers on a
     different rc cannot resolve this package."
   - Same check for `peerDependencies["@effect/vitest"]`.
5. Assert `@effect-cucumber/gherkin`'s packed manifest has no `effect` key in
   any dependency field.
6. Run `pnpm exec publint "$TMP/<name>/package"` and fail on a non-zero exit.

Clean up the temp dir on exit (`trap`). Print a `✓` line per assertion and a
final `pack shape: OK` on success.

  <name>Task 2: Write the READMEs with @rc-carrying install instructions</name>
  <files>README.md, packages/gherkin/README.md, packages/vitest/README.md</files>
  <action>
There is no root `README.md` and no per-package README today. npm includes a
package's `README.md` in its tarball automatically, so each package needs its
own.

Write three files. Keep them short — this is a pre-release library with no
public API yet, and AGENTS.md §4 ("say only what is true") applies: do not
document behavior that does not exist. Point readers at `spec/` for the
contract and `spec/roadmap.md` for what is built vs. planned.

**`README.md` (root)** — what the project is (an Effect-native Gherkin/Cucumber
runner for vitest), the core value proposition in one paragraph (a Scenario's
dependencies are checked at compile time via a `Layer`), a **Status** section
saying plainly that nothing is published to npm yet and no library code has
shipped, the install block below, a Requirements section, and links to
`spec/`, `AGENTS.md`, `CONTRIBUTING.md`.

**`packages/vitest/README.md`** and **`packages/gherkin/README.md`** — one
paragraph on the package's role (per `spec/overview.md` § Packages), the same
Status note, and the same install block scoped to that package.

Every install line must carry `@rc`. Use this exact shape:

```sh
pnpm add -D @effect-cucumber/vitest effect@rc @effect/vitest@rc vitest
```

And immediately below it, a call-out that explains *why* — this is the single
most likely first-run failure for a new user:

> **The `@rc` tags are required.** npm's `latest` tag for `effect` still points
> at the v3 line (`3.22.x`); `4.0.0` has no stable release yet. Installing
> without `@rc` gets you Effect v3 and a wall of type errors against a v4-only
> library. The same applies to `@effect/vitest`, whose `latest` is also on the
> v3 line.

State the required Effect line explicitly: "Requires Effect v4
(`4.0.0-rc.112` or newer) and vitest `>=4.1.0 <5.0.0`." Add a Node requirement
line matching the `engines` field (`>=20`).

Do not invent usage examples for an API that does not exist yet.

After writing, re-run the formatter and linter — dprint formats markdown.
  </action>
