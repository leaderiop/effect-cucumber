    - Row F9, reason `UnknownPlaceholder` (check beta): in a pickle correlated to an Outline, a
      leftover `<name>` whose name is NOT one of that Outline's Examples header columns. The
      warning message must NAME the columns that DO exist, so the author can see the mismatch.
      This is the signature of upstream cucumber/gherkin#22 (still open, "Gherkin quietly ignores
      unfinished table cells"): a header row missing its trailing pipe silently drops the last
      column, header and body cell counts stay consistent so no upstream guard fires, and the
      placeholder survives as literal text. Reuse the same three scan targets and the same fixed
      regex literal from Task 1 — do not declare a second regex. Note that this check can also
      fire on `<div>`-shaped text inside an Outline; that is the accepted heuristic cost, and it
      is why this is a warning and not an error.
    - Row F11, reason `DuplicateExamplesColumn`: any `Examples:` block whose header cells contain
      the same value twice. Detect from `AstScenarioInfo.examplesHeaders`, which preserves
      duplicates — a `Set` would erase the very thing being detected. Verified upstream: the first
      column wins for BOTH occurrences, so `<a> twice <a>` with header `| a | a |` and body
      `| 1 | 2 |` compiles to `1 twice 1` with no error. Upstream cucumber/gherkin#28. The message
      names the duplicated column and the Examples block's line.
    - Row F13, reason `EmptyRule`: any AST `Rule` with zero Scenario children. Verified: produces
      zero pickles, silently. The message names the Rule and its line.
    - Row F14, reason `SuspectedSwallowedStep`: any Scenario or Background whose AST `description`
      is non-empty. Verified: a typo'd step keyword written BEFORE any valid step is silently
      swallowed into `scenario.description`; the AST has one step, the pickle has one step, and
      no error is raised at any layer, so a step the author wrote simply does not exist. The same
      typo AFTER a valid step is a loud parse error, so the behavior is position-dependent and
      will not be found by casual testing. The message must quote the description VERBATIM (no
      truncation) and state that a description is legal Gherkin, so this is a heuristic. Do NOT
      attempt edit-distance matching against dialect keywords — `02-RESEARCH.md` marks that
      speculative and out of scope.
      Note this is additive to, not a replacement for, plan 02-07's mitigation of quoting the
      description inside the `ZeroStepScenario` error message; both exist.

    Warnings must be emitted in deterministic document order so a test can assert the array
    contents. `validateFeature` returns them; it does not print, log, or throw them. How a warning
