<objective>
Build `@effect-cucumber/gherkin`'s own `DataTable` wrapper — the piece ADR-EC-008's correction says
this package must implement itself because `.hashes()`/`.raw()`/`.rowsHash()` live in
`@cucumber/cucumber`, a runner this library does not depend on (ADR-EC-011).

Purpose: a Gherkin table arrives as `{ rows: [{ cells: [{ value }] }] }` and nothing else. Every
step that wants rows-as-records currently has to write the same loop. This plan gives it one
implementation, with the two silently-wrong shapes this repo refuses to ship — a duplicate header
column, and a `rowsHash()` over a table that is not two columns wide — surfaced as named failures
instead of last-cell-wins.

Output: `DataTableError` on `Errors.ts`, a new `DataTable.ts` module, and `DataTable.test.ts`.

  reason: Schema.Literals([/* ... */]),
  uri: Schema.String,

Locked constraints on that pattern, already recorded in `Errors.ts`'s own doc comment:
- `Schema.Literals([...])` — the ARRAY form. The variadic multi-argument form throws.
- No custom constructor. `@effect/tsgo`'s `overriddenSchemaConstructor` diagnostic rejects any
  constructor override on a `Schema.TaggedError` subclass, and `tsc -b` is a gate.
- Every construction site must pass `Option.some(x)` / `Option.none()` explicitly. Omitting an
  `Schema.OptionFromUndefinedOr` key entirely fails construction outright.

Define `export type DataTableErrorReason` as a union type (not an enum — `erasableSyntaxOnly` is on
workspace-wide) with exactly these four members:

  two rows into one entry.
- `"RowsHashRequiresTwoColumns"` — `.rowsHash()` was called on a table whose rows are not exactly
  two cells wide. `@cucumber/gherkin`'s parser already rejects an inconsistent cell count within
  one table (fixture row F10), so every row has the same width; a width other than 2 is the
  remaining failure.

- `readonly rows: ReadonlyArray<PickleTableRow>` — the raw pickle rows, kept as an escape hatch for
  the same reason `ParsedFeature.document` and `.pickles` are kept.
- `readonly raw: () => ReadonlyArray<ReadonlyArray<string>>`
- `readonly hashes: () => Effect.Effect<ReadonlyArray<Readonly<Record<string, string>>>, DataTableError>`
- `readonly rowsHash: () => Effect.Effect<Readonly<Record<string, string>>, DataTableError>`

Export `const makeDataTable = (table: PickleTable, uri: string, line: number): DataTable`.

Semantics, each of which must be stated in a doc comment on the member it governs:

`raw()` — TOTAL, never fails. Returns every row's cell values in order, INCLUDING the header row.
This matches `@cucumber/cucumber`'s own `raw()` and is why `hashes()` exists separately. An empty
table (`rows: []`) returns `[]`.

`hashes()` — reads `rows[0]` as the header and maps every subsequent row to a record keyed by the
header cell values. Returns `[]` for a header-only table (F30) and for an empty table. Fails with
`DataTableError` reason `DuplicateHeaderColumn` when the header row repeats a value, with `column`
set to the repeated name (the first repeat in left-to-right order), `row` set to `Option.none()`
(the fault is in the header, not a body row), and a message quoting the WHOLE header row verbatim.
Build each record with `Object.fromEntries(...)`, never with a `result[key] = value` assignment
loop — see the threat model below; this is a correctness requirement, not a style preference.
Cell counts are guaranteed equal across rows by `@cucumber/gherkin`'s own parser (fixture F10), so
there is no ragged-row branch; say so in the comment rather than writing a defensive branch that
can never be reached and can never be tested.

`rowsHash()` — reads EVERY row (there is no header row in this shape) as a key/value pair. Fails
with reason `RowsHashRequiresTwoColumns` when any row's `cells.length` is not exactly 2, with `row`
set to the 1-based ordinal of the first offending row and a message stating both the expected width
(2) and the actual width, and quoting that row's cell values verbatim. Fails with reason
`DuplicateRowKey` when two rows share a key-column value, with `column` set to that key and `row`
set to the 1-based ordinal of the SECOND occurrence. An empty table returns `{}`. A header-only
one-column table therefore fails `RowsHashRequiresTwoColumns` at row 1 — that is correct and
should be tested, not special-cased.

Every failure is produced with `Effect.fail(new DataTableError({ ... }))` and every
`Option`-typed field is passed explicitly as `Option.some(x)` or `Option.none()` — omitting a key
fails construction outright (Errors.ts note (a)).

Write the module doc comment in this package's established register — it explains WHY, not what.
Cover at minimum:
(a) ADR-EC-008's correction: `.hashes()`/`.raw()`/`.rowsHash()` are not free from
    `@cucumber/gherkin`; they live in `@cucumber/cucumber`, which ADR-EC-011 keeps out of this
    dependency graph, so this package implements its own thin wrapper.
(b) Why `raw()` is pure while `hashes()`/`rowsHash()` return `Effect`: the two fallible accessors
    have real failure modes that `@cucumber/cucumber` resolves by letting the last cell win, and
    this package's whole reason for existing (see `Validate.ts`) is that a silently-wrong result is
    worse than a loud one. The asymmetry is deliberate. A step body is already a generator under
    ADR-EC-005, so `yield* table.hashes()` costs nothing at the call site.
(c) That ADR-EC-008's worked example passes `table.hashes()` directly into a decoder. That fence is
    a `ts` fence — reference material, not compiled (AGENTS.md §2) — and it also predates
    ADR-EC-021's `Effect` migration and effect v4's rename of `Schema.decodeUnknown` to
    `Schema.decodeUnknownEffect`. Plan 04-05 records the correction in `spec/`; this note is its
    source text.

Style: no semicolons, double quotes, 120-column limit, no trailing commas. Do not use
