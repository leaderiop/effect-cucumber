From `packages/gherkin/src/Correlate.ts`, the one construction site (around line 385-413):
```ts
const resolveStep = (pickleStep: PickleStep, byStepId: ReadonlyMap<string, AstStepInfo>, uri: string): ParsedStep => {
  // ...throws LoadFeatureError("ParseFailed") on a missed lookup...
  return {
    id: pickleStep.id,
    text: pickleStep.text,
    keyword: info.step.keyword.trim(),
    keywordType: info.step.keywordType ?? StepKeywordType.UNKNOWN,
    origin: info.owner,
    line: info.step.location.line,
    argument: Option.fromUndefinedOr(pickleStep.argument)
  }
}
```

Upstream fact pinned by plan 04-01 in `upstream-pin.test.ts`, which the ordering rule depends on:
`argumentIndex` holds a NUMBER (`1` and `2`, in source order) only when a step carries both a
DocString and a DataTable. When a step carries only one argument, the `argumentIndex` KEY IS STILL
PRESENT and its VALUE is `undefined` — `compile()`'s `pickleDocString()` / `pickleTable()` are
unconditional object literals and `createPickleArguments()` calls them with `argumentIndex:
undefined` in the single-argument branches. So the ordering rule must read the VALUE
(`Option.fromUndefinedOr(argumentIndex)`) and must never test key presence: `Object.hasOwn(...,
"argumentIndex")` is `true` for every step and therefore discriminates nothing.

Create `packages/gherkin/src/StepArguments.ts`.

Imports: `import * as Option from "effect/Option"`, `import type { PickleStepArgument } from
"@cucumber/messages"` (package barrel, not a deep `dist` path), and
`import { type DataTable, makeDataTable } from "./DataTable.ts"`.

Export an interface `DocString`:
- `readonly _tag: "DocString"`
- `readonly content: string`
- `readonly mediaType: Option.Option<string>` — REQUIRED field holding an `Option`, never
  `mediaType?: string`. ADR-EC-022 put the whole public surface on `Option<T>`; a TS-optional field
  here would reintroduce exactly the `exactOptionalPropertyTypes` asymmetry that ADR removed.

Per ADR-EC-008's correction, a DocString needs no wrapper — it is plain data with no accessors.
Say so in the doc comment, and say why the `_tag` exists anyway: it is what makes the union below
discriminable, not a hint that methods are coming.

Export `export type StepArgument = DocString | DataTable`. Both arms already carry a literal
`_tag`, so a consumer discriminates with a plain `switch (argument._tag)` and never with an
`in` check or an `instanceof`.

Export `export const stepArgumentsOf = (argument: PickleStepArgument | undefined, uri: string, line: number): ReadonlyArray<StepArgument>`.

Behaviour, each point documented on the function:
- `undefined` (a step with no argument) returns `[]`. Never `Option.none()`, never a one-element
  array holding a placeholder — an empty array is the honest representation and lets a consumer
  spread it unconditionally.
- A DocString alone returns one `DocString` with `mediaType` built via
  `Option.fromUndefinedOr(docString.mediaType)`.
- A DataTable alone returns one `DataTable` built via `makeDataTable(dataTable, uri, line)`.
- Both present returns BOTH, ordered ascending by the upstream `argumentIndex`.

The ordering rule must be written so it cannot silently break on the pinned upstream fact:
`argumentIndex` holds a NUMBER (`1`/`2`, in source order) only when a step carries both arguments
(F25 and F33); when a step carries only one, the KEY IS STILL THERE but its VALUE is `undefined`
(fixtures F29/F30/F31). Build the candidate list in the fixed fallback order DocString-then-
DataTable, then reorder with `toSorted` on
`Option.getOrElse(Option.fromUndefinedOr(argumentIndex), () => 0)`. Read the VALUE, as that
expression does — never branch on `"argumentIndex" in x` or `Object.hasOwn(x, "argumentIndex")`,
which are `true` for every step and would therefore discriminate nothing. Do NOT use `.sort(` —
oxlint's `unicorn(no-array-sort)` is error-level and `toSorted` is also non-mutating, which matters
because the candidate list is built from readonly upstream data. A comment must state that the
fallback order only ever applies to a single-element list (because upstream always assigns both
indices when both arguments exist), so it is a safety net rather than a competing convention — and
must name `upstream-pin.test.ts` as the place that fact is asserted.

Write a module doc comment covering:
(a) Why this module exists separately from `DataTable.ts`: `DataTable.ts` is about ONE table's
    accessors, this is about a STEP's arguments as an ordered set. Keeping them apart is what lets
    `DataTable.test.ts` stay parser-free.
(b) Why the result is an ordered ARRAY and not a `{ docString, dataTable }` record: the roadmap's
    success criterion is a documented, tested ARGUMENT ORDER, and a record has no order. Phase 5's
    step-body signature spreads this array after the cucumber-expression arguments; a record would
    force every consumer to re-derive the order from `argumentIndex` themselves, which is exactly
    the duplication `Correlate.ts`'s "do not re-derive what compile() already did" rule forbids.
(c) That `ParsedStep.argument` stays the RAW `PickleStepArgument` and this is an ADDITIONAL field,
    not a replacement. `Correlate.test.ts` has a test asserting the raw argument carries no
    `hashes`/`raw`/`rowsHash` property; that test must keep passing, and it does, because the
    wrapper lives on a different field.

Style: no semicolons, double quotes, 120 columns, no trailing commas, no import from `./index.ts`.
