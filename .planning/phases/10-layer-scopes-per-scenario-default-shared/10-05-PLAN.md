<objective>
Deliver `10-CONTEXT.md`'s D-02: a real-`vitest`-CLI gate proving roadmap Phase 10 Success
Criterion 3's literal clause — "the Feature yields identical results run whole vs. filtered to a
single Scenario."

No in-process assertion can make that claim. A test cannot re-invoke the CLI with a narrower
selection and compare its own status across the two runs, and ADR-EC-018 names exactly that
divergence as the symptom of the defect: "a suite that passes run as a whole can fail under `-t`
filtering (which changes which Scenario runs 'first' against the shared clock), or vice versa."

Purpose: RUN-03 and RUN-04, from outside the test process.
Output: `scripts/verify-shared-layer-once.sh`, its `package.json` entry, and its CI step.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| inside the test process → outside it | the boundary this whole plan exists to cross; every claim here is about what an external observer of the runner's own report can see |
| a Scenario title in `emission.test.ts` → a title constant in the gate | two copies of one string, in two files, with no compiler between them |
| a gate script → the CI merge gate | a script nobody runs is a convention, not a gate |

No network, no authentication, no persistence, no runtime user input. The gate reads a JSON report
the runner wrote into a `mktemp -d` directory it removes on exit.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-05-01 | Tampering | title constants drifting from the fixture | mitigate | `title_is_declared` runs before ANY vitest invocation and matches by exact `Scenario: <title>` line suffix, not containment. A containment grep passes a suffix rename and turns a later status assertion vacuous — measured and recorded in `verify-tags-filter.sh`'s own comment, which is copied here |
| T-10-05-02 | Tampering | a run that collected nothing | mitigate | Every run carries its own vacuity control: run A asserts a non-zero total, runs B and C assert at least one passed. A file that fails to collect produces zero results, against which every status assertion is trivially true |
| T-10-05-03 | Repudiation | reporter output as the signal | mitigate | The report is parsed as STRUCTURED JSON with `node -e`. No glyph is ever used as a match pattern; glyph output varies with TTY detection, colour support and reporter choice, and a gate keyed to it breaks silently in CI or matches nothing and passes |
| T-10-05-04 | Tampering | the gate never running | mitigate | Wired as a root `package.json` script AND as a CI step, with a cross-check asserting every `pnpm `-prefixed `run:` in the workflow names a real script. STATE.md records this as the exact problem plan 01-06 existed to fix |
| T-10-05-05 | Information Disclosure | temp report files | accept | Written under `mktemp -d` and removed by a `trap ... EXIT`, matching every sibling gate. They contain test titles and statuses from this repo's own suite and nothing else |
| T-10-05-06 | Repudiation | overclaiming what the gate adds | mitigate | Task 2 MEASURES three mutations against both `pnpm test` and the gate and requires the METHOD NOTE to match the measurement, including the outcome where no `pnpm test`-green mutation exists. A gate whose header claims an asymmetry it does not have trains a reader to disbelieve the next one |
| T-10-05-07 | Denial of Service | three vitest invocations in CI | accept | Guarded to the Node 24 matrix leg only, the same trade-off the `verify:tags-filter` step already makes for the same stated reason |
| T-10-05-SC | Tampering | npm/pip/cargo installs | n/a — accept | No package is installed. The new `package.json` entry is a script, not a dependency; `pnpm-lock.yaml` is untouched and `pnpm install --frozen-lockfile` in CI is unaffected |
