The verified type surface, reproduced by RESEARCH.md against this repo's own compiler
(RESEARCH.md "Code Examples §1" is the authoritative source — read it before writing):

- `StepRegistrar<ROut>` is a callable interface, generic per call site in
  `<Params extends ReadonlyArray<any>, A, E>`, taking `(pattern: string, fn: <union>)` and
  returning `void`.
- The union, IN THIS ORDER: `((...p: Params) => Effect.gen.Return<A, E, ROut | Scope.Scope>)`
  first, then `((...p: Params) => Effect.Effect<A, E, ROut | Scope.Scope>)`.
- `ScenarioDsl<ROut>`: `readonly Given/When/Then/And/But: StepRegistrar<ROut>`.
- `BackgroundDsl<ROut>`: `readonly Given/And: StepRegistrar<ROut>` only (ADR-EC-017 — real
  Gherkin grammar permits only Given/And in a Background).
- `FeatureDsl<ROut> extends ScenarioDsl<ROut>` adding
  `readonly Background: (define: (dsl: BackgroundDsl<ROut>) => void) => void` and
  `readonly Scenario: (name: string, define: (dsl: ScenarioDsl<ROut>) => void) => void`.

From plan 05-01: `packages/vitest/src/Registry.ts` exports `createRegistry<Fn>(featureName)`
with `register(keyword, pattern, body)`. `Step.ts` does not import it — 05-03 wires them.

`Effect.gen.Return` and `Effect.fn` are declared in
`packages/vitest/node_modules/effect/dist/Effect.d.ts` (`gen.Return` around L1877, the `fn`
namespace around L16605). Read them if a signature question arises; do not guess.

    (a) The step-function union lists `Effect.gen.Return` FIRST and `Effect.Effect` SECOND.
        TypeScript reports the first union member it fails against. With the Effect-returning
        branch first, the reported mismatch is "a Generator is missing toJSON,
        [NodeInspectSymbol], [TypeId], pipe" — a shape error the `@effect/tsgo` plugin has no
        reason to interpret as a context problem, so `effect(missingEffectContext)` never
        fires. The step is still rejected, so every test stays green while ADR-EC-016's
        diagnostic silently stops covering the DSL. Reproduced across four permutations in
        RESEARCH.md Finding 2. Do not reorder these two members, and do not "tidy" them onto
        one line in a way that obscures which is first.

    (b) `Scope.Scope` appears ONLY in the step-function parameter's required-context position,
        as `ROut | Scope.Scope`. It must not appear on `FeatureDsl`, `ScenarioDsl`,
        `BackgroundDsl`, or on any Layer type. `ROut` is exactly the ambient Layer's output —
        the thing the test author reasons about — and leaking `Scope` into it would buy
        nothing. This placement is what lets a step using `Effect.acquireRelease` compile
        against a plain `Layer<World>` while a step using an unprovided `Db` is still
        rejected (RESEARCH.md Finding 8).

    (c) `BackgroundDsl` deliberately omits `When`, `Then` and `But` — ADR-EC-017; real Gherkin
        grammar permits only Given/And in a Background. Reaching for `When` on it is `TS2339`,
        which is the intended behavior, not a gap.

    (d) `Params extends ReadonlyArray<any>`, not `unknown[]`. The spec's published BEH-EC-003
        signature uses `unknown[]`, which does not accept a generator's inferred parameter
        tuple cleanly. That same published signature also writes the generator branch as
        `Generator<any, A, any>` — a vacuous yield type against which a step requiring an
        unprovided service compiles clean, exit 0 (RESEARCH.md Finding 4). Do not copy
        BEH-EC-003 as written; plan 05-06 corrects the spec to match this file.

    (e) `R` is bound to the enclosing `describeFeature`'s `ROut` through `StepRegistrar<ROut>`;
        it is NOT a free type parameter of the registrar's call signature. A per-call-site `R`
        infers to whatever the body needs and constrains nothing — PITFALLS Pitfall 3's
        vacuous-generic trap.

    Give every interface member its own `/** ... */` doc comment stating the verified fact, per
    `StepArgs.ts`'s per-member pattern. Mark every property `readonly`.

    Do not add explicit variance annotations (`in`/`out`) to any of these types. Effect v4
    declares `Effect<out A, out E, out R>` (R covariant) and `Layer<in ROut, out E, out RIn>`
    (ROut contravariant); the inferred variance here is correct, and annotating risks pinning
    it wrong (RESEARCH.md Finding 8, "Variance context").

    Nothing in this file may be widened with `any` outside the two documented positions
    (`Params extends ReadonlyArray<any>`). One `any` in a step body's type disables the entire
    INV-EC-003 guarantee (PITFALLS Pitfall 6).

    than aliased.

    ADR-EC-005 auto-wrap that makes the step text observable as the span name. Otherwise return

    both with no cast (RESEARCH.md Finding 7) — so the runtime guard is the only thing standing

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-supplied step body → `register` | The only value crossing a boundary is a function the test author wrote in their own test file. It is not untrusted input; it executes with the author's own privileges either way. |
| type surface → CI verdict | `Dsl.ts` is what makes an unprovided-service step a build failure. Its correctness is a CI-integrity property, not a runtime-security one. |

No network, no I/O, no parsing of external data, no auth, no crypto, no persistence.
