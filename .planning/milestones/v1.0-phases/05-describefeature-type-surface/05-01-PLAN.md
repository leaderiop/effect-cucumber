    Create `packages/vitest/src/Registry.ts` exporting `createRegistry`, a factory that closes
    over private mutable state and is never a module singleton. DSL-04 forbids a module-level
    `let currentScope` or an exported mutable registry outright; PITFALLS Pitfall 14 records why.

    Concrete surface:
    - `RegistryScopeKind` = the string-literal union `"feature" | "background" | "scenario"`.
      Do not use an enum — `erasableSyntaxOnly` is on workspace-wide.
    - `RegistryScope` — `readonly kind: RegistryScopeKind`, `readonly name: string | null`
      (`null`, not an optional property: `exactOptionalPropertyTypes` is on, and a Background
      has no name while a Scenario does).
    - `StepKeyword` = `"Given" | "When" | "Then" | "And" | "But"`.
    - `StepDefinition<Fn>` — `readonly keyword: StepKeyword`, `readonly pattern: string`,
      `readonly body: Fn`, `readonly scope: RegistryScope`.
    - `createRegistry = <Fn>(featureName: string) => ...` returning an object literal with:
      `pushScope(scope: RegistryScope): void`, `popScope(): void`,
      `currentScope(): RegistryScope`,
      `register(keyword: StepKeyword, pattern: string, body: Fn): void`, and
      `definitions(): ReadonlyArray<StepDefinition<Fn>>`.
      The constructor seeds the stack with a single root scope
      `{ kind: "feature", name: featureName }`. `register` appends a record carrying the
      current top-of-stack scope. `definitions()` returns a COPY, never the live array.
      `popScope()` at the root must throw an `Error` whose message names the condition
      (a scope underflow means a container callback returned twice or a `pushScope` was lost) —
      it must not silently empty the stack.
    - Derive the public shape as `RegistryShape<Fn> = ReturnType<typeof createRegistry<Fn>>`,
      following `ParameterTypeStoreShape`'s precedent, so the shape and the factory cannot
      drift. If an instantiation expression in that position does not type-check under this
      repo's config, declare an explicit interface instead AND annotate `createRegistry`'s
      return type with it — never leave a hand-written shape unenforced against the factory.

    `Fn` stays a free type parameter: `Registry.ts` must not import from `Dsl.ts`,
    `describeFeature.ts`, or `@effect-cucumber/gherkin`. It is a container, and keeping it
    dependency-free is what lets it land in wave 1 ahead of the type surface.

    `Registry` is deliberately NOT exported from `packages/vitest/src/index.ts` (plan 05-03 owns
    that barrel). It is an internal stage with no standalone consumer contract, following
    gherkin's precedent of not exporting `Parser`/`Pickles`/`Correlate`. Say so in the module
    doc comment.

    Write the module doc comment in the house style: a header stating what is not visible from
    the code, with lettered notes — at minimum (a) why this is a factory rather than a module
    singleton, naming DSL-04 and Pitfall 14, and (b) why `definitions()` copies.

    Every exported binding needs an explicit return-type/type annotation: `composite: true`
    demands it for declaration emit.

    Then create `packages/vitest/test/Registry.test.ts`. Import `../src/Registry.ts` by relative
    path with the explicit `.ts` extension, never `../src/index.ts`
    (`effect/no-import-from-barrel-package` runs with `checkRelativeIndexImports: true`). Use
    full-sentence `describe` titles (`vitest/no-identical-title` is error-level). Assert:
    1. Two `createRegistry` calls return two different objects (`expect(a).not.toBe(b)`), with
       the comment explaining that reference inequality alone does not prove isolation.
    2. Registering into `a` leaves `b.definitions()` empty — the assertion that actually catches
       a closure over module-level state.
    3. Pushing a scenario scope on `a` leaves `b.currentScope()` reporting its own feature root.
    4. `definitions()` returns a snapshot: capture the result, register once more, and assert the
       captured array's length is unchanged.
    5. `popScope()` at the root throws with a message (`expect(() => r.popScope()).toThrow("...")`
       — a bare `toThrow()` fails oxlint's `vitest/require-to-throw-message`).
    6. A step registered inside a pushed scenario scope carries that scope on its
       `StepDefinition`, and one registered after `popScope()` carries the feature root again.
