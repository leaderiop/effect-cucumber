<objective>
Deliver ADR-EC-008's actual promise: a data table decodes through `Schema` into typed rows, and a
row that fails names the offending row and column.

Purpose: `Schema.decodeUnknownEffect(Schema.Array(Row))(table.hashes())` already fails with a
`SchemaError` whose message reads `Expected string\n  at [1]["name"]`. That is a generic parse
failure — it names an array index into a value the step author never constructed, and says nothing
about which feature file, which step, or which table row. This plan converts that into a
`DataTableError` carrying `uri`, the step `line`, the 1-based body-row ordinal, and the column
name, which is what the roadmap's success criterion 2 actually asks for.

Output: a dependency pin for effect's issue-tree shape, `decodeHashes` on `DataTable.ts`, and its
tests.

  <action>
Add an exported `decodeHashes` to `packages/gherkin/src/DataTable.ts`. Add
`import * as Schema from "effect/Schema"` and `import * as SchemaIssue from "effect/SchemaIssue"`
as submodule namespace imports.

Signature — mirror `Schema.decodeUnknownEffect`'s own type-parameter shape rather than inventing
one, so the decoding-services channel propagates correctly:

`export const decodeHashes = <S extends Schema.Constraint>(rowSchema: S) => (table: DataTable): Effect.Effect<ReadonlyArray<S["Type"]>, DataTableError, S["DecodingServices"]>`

`rowSchema` describes ONE row, not the array. `decodeHashes` wraps it in `Schema.Array(rowSchema)`
itself, because the array index in the resulting issue path is exactly the `.hashes()` body-row
index and that correspondence is the whole mechanism. Document that in a comment: a caller who
passes `Schema.Array(Row)` would get paths one level deeper and the row ordinal would silently be
wrong, so this function owns the wrapping.

Implementation shape:
1. `yield*`/flatMap `table.hashes()` first, so a `DuplicateHeaderColumn` failure propagates
   unchanged — it is a table-shape fault, not a decode fault, and must keep its own reason tag.
2. Run `Schema.decodeUnknownEffect(Schema.Array(rowSchema))` over the hashes array.
3. `Effect.mapError` the resulting `SchemaError` into a `DataTableError` with reason
   `"RowDecodeFailed"`, `uri` and `line` from the table, `cause` `Option.some(schemaError)`, and
   `row`/`column` derived as described below.

Add a module-private helper — name it `firstIssuePath` — that walks a `SchemaIssue.Issue` and
returns the first leaf's accumulated path as a `ReadonlyArray<PropertyKey>`. It concatenates each
`Pointer.path` on the way down and recurses through `Composite`'s children; any other issue tag is
a leaf. Return `[]` when no `Pointer` was traversed. This is the exact walk
`schema-issue-pin.test.ts` asserts, so keep the two in step — a comment on the helper should say
that the pin is the reason it is safe to rely on the shape.

Derive the locator from that path:
- `row` = `Option.some(index + 1)` when `path[0]` is a `number` (1-based body-row ordinal, so it
  matches how a human counts rows under the header), otherwise `Option.none()`.
- `column` = `Option.some(path[1])` when `path[1]` is a `string`, otherwise `Option.none()`.
- Both `Option.none()` when the path is empty (a top-level type failure — pinned as case 5 in
  Task 1). Never fabricate a row 1 in that case.

Message format — the no-truncation policy of `Errors.ts` note (b) applies, so nothing here is
elided or shortened. Compose it from these parts, in this order, so the message answers "which
file, which step, which row, which column, what was wrong, and what was the value":
`Row {row} of the DataTable at {uri}:{line} failed to decode` + `, column {JSON.stringify(column)}`
when a column was recovered + `: {schemaError.message}` + ` The row was {JSON.stringify(theRow)}.`
where `theRow` is the offending `.hashes()` record when the ordinal was recovered and the whole
hashes array otherwise. When no row was recovered, open with
`The DataTable at {uri}:{line} failed to decode` instead. Use `JSON.stringify` for quoting, which
is what `Errors.ts` already does at its most consequential call sites.

Extend `DataTable.ts`'s module doc comment with one more numbered note explaining why
`decodeHashes` is a standalone exported function rather than a `decode` method on the `DataTable`
interface: a generic method on an interface would have to carry the `Schema.Constraint` type
parameter through the interface declaration, and the `DataTable` value is constructed per step by
`Correlate.ts` where no schema is in hand. Keeping it standalone also keeps `makeDataTable`'s
return value a plain data record.

Style: no semicolons, double quotes, 120 columns, no trailing commas, no `.sort(`, no import from
`./index.ts`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.feature` table content → `Schema` decoder | Cell values are untrusted strings crossing into a caller-supplied decoder that may run arbitrary transformations |
| `SchemaError` internals → `DataTableError.message` | A dependency's message text is embedded in this library's public error surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06 | Tampering | `firstIssuePath` walking an attacker-influenced issue tree in `packages/gherkin/src/DataTable.ts` | mitigate | The walk is bounded by the schema's own AST depth, which the caller authored — not by table content. It reads only `_tag`, `path` and the composite children field, and never evaluates or indexes user data with a recovered key. `row`/`column` are narrowed by an explicit `typeof` check before use, so a non-number index cannot become `NaN + 1` |
| T-04-07 | Information disclosure | `DataTableError.message` embedding the offending row verbatim | accept | Inherited unchanged from `Errors.ts` note (b)'s locked no-truncation policy. Introducing a truncation step here would create a second, inconsistent policy for the same class of content |
| T-04-08 | Denial of service | A caller-supplied `Schema` with an expensive decoder run per row | transfer | The decoder is the consuming project's own code and runs inside its own step body's Effect. `decodeHashes` adds one pass and no retry, no backtracking, and no recursion over table content |
| T-04-SC | Tampering | npm/pip/cargo installs | mitigate | Not applicable — zero dependencies added. `effect` is already a declared peer (ADR-EC-021); `pnpm-lock.yaml` must be byte-identical after this plan |
