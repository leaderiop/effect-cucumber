<objective>
Build the type-level half of MATCH-01. `StepMatcher` extracts arguments at runtime; nothing in the
type system yet says that `{int}` means `number`. `StepArgs<P>` is the mapping, derived from the
pattern string literal, and it is what Phase 5's `Given`/`When`/`Then` signatures will use to give a
step body already-coerced parameter types.

Roadmap success criterion 1 requires the coercion to be asserted "at runtime and in a type test".
This plan owns the type test; plan 03-04 owns the runtime assertion.

This module has zero imports — local or third party — and produces zero emitted JavaScript. It is
the most independent thing in the phase, which is why it runs in wave 1 alongside 03-01.

Purpose: MATCH-01, roadmap success criterion 1 (the type-test half).
Output: `src/StepArgs.ts` and the `@ts-expect-error`-based type test `test/StepArgs.types.ts`.
</objective>

    Export an interface `BuiltInParameterTypeMap` whose eleven keys are the built-in parameter type
    names and whose value types are the verified TypeScript types listed in the `<interfaces>` block
    above: `int` number, `float` number, `word` string, `string` string, `double` number,
    `bigdecimal` string, `byte` number, `short` number, `long` number, `biginteger` bigint, and the
    empty-string key `""` mapped to string. Every member gets a doc comment; the four that
    MATCH-01 names by ID (`int`, `float`, `string`, `word`) say so explicitly, and `bigdecimal`,
    `biginteger` and `""` each carry a note that the type is the VERIFIED runtime result and not the
    intuitive one.

    Export a type `StepArgs<P extends string, Custom extends Record<string, unknown> = {}>` that
    resolves a cucumber-expression pattern string literal to the tuple of argument types a step body
    receives, left to right.

    Implement it by recursive template-literal inference on the brace pair, not character by
    character — a per-character recursion exhausts TypeScript's instantiation depth on a realistic
    step pattern:

    - Match `P` against the template `${infer Head}{${infer Name}}${infer Tail}`. TypeScript infers
      the shortest possible `Head`, so this walks brace pairs left to right.
    - If `Head` ends with a backslash (test with a second template inference of the form
      `${string}\\`), the parameter is escaped: emit NO element and recurse on `Tail`.
    - Otherwise emit one element, resolved in this precedence order, and recurse on `Tail`:
      first `Name extends keyof BuiltInParameterTypeMap` yields `BuiltInParameterTypeMap[Name]`;
      then `Name extends keyof Custom` yields `Custom[Name]`; otherwise `unknown`. Built-ins take
      precedence deliberately, mirroring the runtime rule that a custom type may never shadow a
      built-in name.
    - When `P` matches no brace pair, the tuple terminates as the empty tuple.

    The result must be a genuine tuple type usable as a rest-parameter list, i.e. built by prepending
    with the spread form so that `StepArgs<"I have {int} cukes"> extends [number]` and
    `(...args: StepArgs<P>) => void` is legal. It must not widen to an array type.

    Optional groups and alternations need no special handling — they contain no brace pair — but say
    so in the doc comment with the verified examples `apple(s)` and `I am happy/sad`, so nobody adds
    dead handling for them later.

    Write a module doc comment covering: (a) what this module is for — Phase 5's `Given`/`When`/
    `Then` signatures thread `StepArgs<P>` into the step body so `{int}` arrives as `number` at
    compile time, which is the type-level half of MATCH-01 and is what makes DSL-06 need no separate
    typed-example-row mechanism; (b) that every entry of `BuiltInParameterTypeMap` was verified by
    running the installed `@cucumber/cucumber-expressions@20.1.0`, and is pinned in
    `test/expressions-pin.test.ts`, so this map and that pin must be changed together; (c) that an
    unknown `{name}` resolves to `unknown` rather than to a type error, because a custom parameter
    type is registered as runtime data and cannot be recovered from a string literal — the `Custom`
    map is the escape hatch for a caller who wants it typed.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| runtime coercion (`Argument.getValue`) → declared type (`StepArgs<P>`) | The only thing keeping these two in agreement is a hand-maintained map plus the upstream pin; a divergence is a silent lie told by the type system |
| a type test → the CI gate that runs it | A type test that is never compiled, or that is compiled but asserts only assignability, passes while proving nothing |
