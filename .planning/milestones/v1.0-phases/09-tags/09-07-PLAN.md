Implementation:
- The parameter is REQUIRED and has no default. Throw a plain `Error` naming `gherkinTags` when it is
  an empty string or an empty array — a helper asked to expand nothing returns nothing, and a config
  declaring nothing makes every tag in the suite undeclared. Silence there is the failure mode, not a
  convenience. This is the same contract the module has always had for empty input.
- Discover files with `globSync(pattern, { dot: false, onlyFiles: true })`. Pass those two options
  EXPLICITLY even though they are already tinyglobby's defaults: both are load-bearing (no dotfile
  trees, no directory entries handed to `readFileSync`), and pinning them means a future default
  change cannot silently widen the scan. Leave `cwd`, `absolute`, `expandDirectories`, `globstar` and

  resolves patterns against `process.cwd()` exactly like every other glob-consuming Node tool a
  consumer already uses. Document that cwd contract in the doc comment; it is the one thing a caller
  can get wrong.
- A pattern that matches nothing returns `[]` and does NOT throw. This is glob semantics, and it is
  deliberately different from the empty-pattern case: a zero-match pattern is indistinguishable from a
  project that legitimately has no `.feature` files yet, so throwing would break a valid config. State
  the residual risk in the doc comment rather than hiding it, and state its compensating signal: a
  missing declaration no longer fails silently anyway, because plans 09-02/09-05 print one located
  warning per Scenario naming the file, the Scenario and the tag.
- Read each matched file with `fs.readFileSync(file, "utf8")`. Results come back relative to
  `process.cwd()` (`absolute` is left at its `false` default) and `readFileSync` resolves relative
  paths against that same directory, so no path juggling is needed — say so in the doc comment so a
  later reader does not "fix" it by adding a `path.resolve`.
- Extract tags line by line: a Gherkin tag line is a line whose TRIMMED form begins with `@`; collect
  every whitespace-delimited token on it that begins with `@`. Track DocString fences — toggle a
  skip flag on a line whose trimmed form starts with three double-quotes or three backticks — so a
  `@`-leading line inside a DocString is not mistaken for a tag line.
- De-duplicate and sort the result ascending, so a config's declared list is stable across runs and
  across filesystem ordering.
