    (5) The semantics, in `buildScenarioEffect`:

    - `yield* runHookBatch(args.hooks.Before)` is the FIRST statement inside the existing `Effect.gen`,
      before the step `for` loop. That single statement is all of D-04: if the batch fails, the
      generator stops advancing and no step runs. The gating is structural, exactly as INV-EC-001's
      step fail-fast is — there is no "did a Before fail" flag anywhere. D-02 and D-03's independence
      and cause-combining live entirely inside `runHookBatch` and are not re-implemented here.
    - The whole composed generator is wrapped with `Effect.onExit(() => runHookBatch(args.hooks.After))`,
      and `Effect.provide(args.layer)` stays the LAST `.pipe` so the returned Effect still requires only
      `Scope.Scope`. `Effect.onExit` and NOT `Effect.ensuring`: `ensuring`'s finalizer error channel is
      `never` in `effect@4.0.0-rc.112`, so an `After` hook that can fail is not even assignable to it,
      and it merges no causes. `onExit`'s documented behaviour — runs on success, failure and
      interruption, and merges the two causes when both fail — is exactly INV-EC-004 plus the
      "a failing After must not mask the step failure" requirement (roadmap SC #4).
    - Because the `onExit` wraps the whole generator and not just the step loop, `After` also runs when
      a `Before` hook failed. That is deliberate, matching D-07's "the guarantee wraps the whole unit,
      not just the narrowest possible span" principle locked for `AfterStep`.
    - The finalizer ignores its `exit` argument (write a zero-parameter arrow). `After` hooks receive no
      arguments — ADR-EC-005's Negative consequence — and giving them the exit would be a signature this
      phase deliberately does not have.

    Do NOT touch the step `for` loop in this task; `BeforeStep`/`AfterStep` are plan 07-05's. Do NOT
    introduce `Effect.forEach`, `Effect.all`, a recovery combinator, or any re-tagging of a step's
    error — note (a) forbids all four and the reasons are recorded there.

    Add two numbered notes to `ScenarioEffect.ts`'s module header in the file's existing house form:
    - `Before` is a GATE built out of one `yield*` and nothing else; the plausible tidy-up is an
      explicit "if any Before failed, skip the steps" check, which reintroduces exactly the bookkeeping
      INV-EC-001 exists to forbid. Name the test that goes red.
    - `After` uses `Effect.onExit`, never `Effect.ensuring`, with the verified type reason; the
      plausible tidy-up is "BEH-EC-006 says `ensuring`, use `ensuring`", which does not compile for a
      fallible hook and, if made to compile by widening the hook type, silently drops the merged cause.
      Note that plan 07-08 corrects BEH-EC-006's text.
