<objective>
Close the one gap `10-VERIFICATION.md` found: a `shared` Layer is still built when the tag
filter has excluded every Scenario in the Feature, as long as the Feature carries at least one
unused step-definition warning.

The mechanism is fully diagnosed and reproduced (VERIFICATION.md `gaps[0]`, and CR-02 in
`10-REVIEW.md` independently). `Runner.ts:630-632` emits the always-passing `⚠ unused step
definition` nodes unconditionally, and on the shared path every emission goes through
`sharedIt.effect`, whose `@effect/vitest@4.0.0-rc.112` implementation flatMaps the memoised
shared-Layer build before running ANY body — including a body that is just `Effect.void`. The
`⚙ AfterAllScenarios` node three lines above it IS correctly suppressed when
`runnableScenarioCount === 0`; the warning node that forces the very build that teardown would
have needed is not.

Purpose: for a `shared` tier holding a testcontainer or a database pool, an explicitly excluded
Feature can currently still pay the cost of starting one — defeating the premise that the
`shared` tier is deferred and observable only when used, and contradicting the documented
`excludeTags` contract that a Scenario the filter removes never becomes a test node at all.

Output: a routing flag on the library's own `EmitOptions`, a second emission route in the shared
path's `TestApi`, and an `emission.test.ts` regression block asserting the build counter stays
at 0 for exactly the combination the gap names.

**Out of scope, deliberately:** CR-01 (a `BeforeAllScenarios` hook's scoped resource is released
after the FIRST Scenario). The verifier assessed it and did NOT count it as a Phase 10 gap —
`Runner.ts` had no executable change in this phase and the defect is orthogonal to which Layer
scope is used. Do not fix it here. It is a candidate follow-up phase.
</objective>
