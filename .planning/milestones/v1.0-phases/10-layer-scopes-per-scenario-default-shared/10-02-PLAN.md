<objective>
Make the opt-in `shared` Layer scope actually behave as `spec/` specifies it: built EXACTLY ONCE
per Feature via `@effect/vitest`'s `layer(...)`, while every Scenario still gets its own fresh
`TestClock`/`TestConsole` (ADR-EC-018) and its own fresh per-Scenario Layer tier (INV-EC-002).

Today `normalizeLayer` collapses `{ shared, perScenario }` into one `Layer.merge` result and the
runner provides that merged Layer inside every Scenario's Effect — so both halves are rebuilt per
Scenario. This plan stops that for the `shared` half only.

Purpose: roadmap Phase 10 Success Criteria 2 and 3, RUN-03 and RUN-04.
Output: a dual provision strategy (ARCHITECTURE.md Pattern 4) made an EXPLICIT field of
`FeatureCollection` and an explicit second `TestApi` implementation, never an implicit consequence
of which branch called in.
</objective>

`layer` from `@effect/vitest`, module-level export:
  `layer<R, E>(layer_: Layer.Layer<R, E>, options?: { memoMap?; timeout?; excludeTestServices?: boolean })`
  returns an overloaded callable:
    one-argument form:  `(f: (it: Vitest.MethodsNonLive<R>) => void) => void`
    two-argument form:  `(name: string, f: (it: Vitest.MethodsNonLive<R>) => void) => void`

`Vitest.MethodsNonLive<R> extends API`, where `API = V.TestAPI<{}>`. It has `effect`, `flakyTest`,
`layer`, `prop`. It has NO `describe` member and NO `live` member (Pitfall 29).

`TestEnv` is INTERNAL to `@effect/vitest` and is NOT exported. Its own definition, read from
`dist/internal/internal.js` line 34, is `Layer.mergeAll(TestConsole.layer, TestClock.layer())`,
built from the PUBLIC modules `effect/testing/TestConsole` and `effect/testing/TestClock`.
`TestClock.layer()` is CALLED — the parens construct a fresh clock layer blueprint. Writing
`import { TestEnv } from "@effect/vitest"` does not compile.

MEASURED during planning, by running real probe suites (both probes deleted afterwards):
  - The ONE-ARGUMENT form runs its callback synchronously in the CURRENT suite and opens NO
    `describe` of its own. Emissions made from inside a `describe` the callback registers — even a
    doubly nested one — still receive the shared context, and the shared Layer built EXACTLY ONCE.
    Measured: sharedBuilds = 1 across two Scenarios nested two `describe` levels deep.
  - The TWO-ARGUMENT form opens its own `V.describe(name, ...)`. Using it would put a SECOND block
    named after the Feature around `Runner.ts`'s own `api.describe(plan.feature.name, ...)`,
    producing `Feature > Feature > Scenario`. That is forbidden by this plan.
  - `excludeTestServices: true` plus a per-emission `Effect.provide(testEnv)` gives full
    per-Scenario clock isolation: measured `Clock.currentTimeMillis` = 0 in a Scenario that ran
    AFTER another Scenario had done `TestClock.adjust("1 hour")` under the same shared Layer.
  - A Rule `extraLayer` composed as `Layer.provideMerge(perScenarioLayer)(extraLayer)` — i.e. with
    the shared tier deliberately absent from the ambient argument — resolves a SHARED service
    correctly at run time, because `Effect.provide` leaves the unsatisfied `RIn` on the Effect and
    the ambient `layer()` context satisfies it. Measured: a Rule Layer computing `netPrice = 90`
    from a shared `listPrice = 100`, with sharedBuilds = 1 and ruleBuilds = 2 across two Scenarios.
