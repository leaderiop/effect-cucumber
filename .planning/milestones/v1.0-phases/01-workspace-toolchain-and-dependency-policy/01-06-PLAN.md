<task type="auto">
  <name>Task 1: Create the check.yml merge gate with a Node 22/24 test matrix</name>
  <files>.github/workflows/check.yml</files>
  <action>
Create `.github/workflows/check.yml`. Structure follows Effect's `check.yml`,
sized down to this project — independent parallel jobs rather than one serial
`check`, so a lint failure and a type failure are reported in the same run.

```yaml
name: CI
on:
  pull_request:
  push:
    branches: [main]
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true
permissions:
  contents: read
```

Four jobs, each starting from the same setup steps:
```yaml
- uses: actions/checkout@v6
- uses: pnpm/action-setup@v6
- uses: actions/setup-node@v7
  with:
    node-version: 24
    cache: pnpm
- run: pnpm install --frozen-lockfile
```

- **`lint`** — `pnpm lint` (this is `oxlint -f unix && dprint check`, so it
  covers both the lint and the format gate in criterion 3).
- **`types`** — `pnpm build` (`tsc -b`), then `pnpm verify:tsgo-gate`. The gate
  step is the one that proves ADR-EC-016 is enforced; it must be a required
  check, not an allowed failure.
- **`test`** — `strategy: { fail-fast: false, matrix: { node-version: [22, 24] } }`,
  with `node-version: ${{ matrix.node-version }}` in the setup-node step, then
  `pnpm test`. Node 24 is Active LTS and the primary target; 22 is kept for
  compatibility breadth, since a testing library gets installed into whatever
  the consumer already has.
- **`package`** — `pnpm verify:pack`, `pnpm circular`, `pnpm verify:spec`.

Notes:
- Do not run `pnpm build` in the `package` job as a separate step if
  `verify-pack.sh` already builds; avoid the duplicate.
- Use plain action tags (not pinned SHAs). Effect pins SHAs; effect-machine uses
  tags, and tags are the right posture for a project this size.
- Every step must be a root `package.json` script that also runs locally — no
  inline command that only exists in CI.
  </action>

<task type="auto">
  <name>Task 2: Add pkg-pr-new preview releases</name>
  <files>.github/workflows/snapshot.yml, package.json, pnpm-lock.yaml</files>
  <action>
With zero published versions, per-PR preview installs are how anyone (including
you) tries a branch without touching the registry.

Install: `pnpm add -Dw pkg-pr-new@0.0.88`

Add a root script:
```jsonc
"snapshot": "pkg-pr-new publish --pnpm ./packages/*"
```

Create `.github/workflows/snapshot.yml`:
```yaml
name: Snapshot
on:
  pull_request:
  push:
    branches: [main]
permissions:
  contents: read
  id-token: write
jobs:
  snapshot:
    runs-on: ubuntu-latest
    steps:
      # same checkout / pnpm / setup-node@24 / install --frozen-lockfile block
      - run: pnpm build
      - run: pnpm snapshot
```

`id-token: write` is what lets pkg-pr-new attest the build; no npm token and no
repository secret are required. The pkg-pr-new GitHub App must be installed on
the repository for the workflow to succeed — that is recorded in this plan's
`user_setup` and is the one step Claude cannot perform.

Do not add the workflow to any branch-protection required-checks set. A preview
publish failing (e.g. because the App is not installed yet) must never block a
merge.
  </action>
