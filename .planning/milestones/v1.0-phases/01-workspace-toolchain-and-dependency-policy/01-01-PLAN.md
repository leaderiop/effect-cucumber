<task type="auto">
  <name>Task 1: Fix and extend tsconfig.base.json to the Effect v4 convention</name>
  <files>tsconfig.base.json, packages/gherkin/tsconfig.json, packages/vitest/tsconfig.json</files>
  <action>
Edit `tsconfig.base.json`:

1. **Delete `"esModuleInterop": false`.** This is the blocking bug. Verified by
   running the repo's own compiler:
   `packages/gherkin/tsconfig.json(3,3): error TS5108: Option 'esModuleInterop=false' has been removed.`
   The option no longer exists in TypeScript 7 — it is not "defaulted", it is
   gone, and leaving it makes `tsc -b` exit 2 unconditionally.

2. **Replace `"isolatedModules": true` with `"verbatimModuleSyntax": true`.**
   `verbatimModuleSyntax` supersedes it and is what Effect's base config uses.

3. **Add** these options (all from `.planning/research/STACK.md` §5.3, each
   verified compiling under `typescript@7.0.2`):
   ```jsonc
   "outDir": "${configDir}/dist",
   "rootDir": "${configDir}/src",
   "incremental": true,
   "moduleDetection": "force",
   "rewriteRelativeImportExtensions": true,
   "erasableSyntaxOnly": true,
   "noUnusedLocals": true,
   "noUnusedParameters": true,
   "noImplicitOverride": true,
   "noFallthroughCasesInSwitch": true,
   "types": []
   ```

4. **Leave the `plugins` block byte-for-byte as it is.** Do NOT add a
   `diagnosticSeverity` key and do NOT change `ignoreEffectWarningsInTscExitCode`
   or `ignoreEffectErrorsInTscExitCode` (both must stay `false`). This exact
   block was empirically confirmed to make `missingLayerContext` (TS377034) and
   `floatingEffect` (TS377001) fail `tsc` with a non-zero exit; plan 01-02
   depends on that being unchanged. Keep
   `namespaceImportPackages: ["effect", "@effect/*", "@effect-cucumber/*"]`.

Then simplify both package tsconfigs, which now inherit `rootDir`/`outDir`
from the base via `${configDir}`:

`packages/gherkin/tsconfig.json`:
```jsonc
{
  "extends": "../../tsconfig.base.json",
  "include": ["src"]
}
```

`packages/vitest/tsconfig.json`:
```jsonc
{
  "extends": "../../tsconfig.base.json",
  "include": ["src"],
  "references": [{ "path": "../gherkin" }]
}
```

**Fallback if `${configDir}` misbehaves** (e.g. output lands at the repo root
instead of inside each package): revert to explicit `"rootDir": "src"` /
`"outDir": "dist"` in each package tsconfig and drop the two `${configDir}`
lines from the base. Record the deviation in the SUMMARY. The `${configDir}`
form is a convenience, not a requirement — the criterion is where the output
lands.
  </action>
  <verify>
`node node_modules/typescript/bin/tsc -b 2>&1` no longer contains `TS5108`.
`grep -c esModuleInterop tsconfig.base.json` returns 0.
`grep -c '"ignoreEffectErrorsInTscExitCode": false' tsconfig.base.json` returns 1.
  </verify>
  <done>
`tsconfig.base.json` has no `esModuleInterop`, carries the Effect v4 option set,
and still registers `@effect/language-service` with both `ignoreEffect*InTscExitCode`
flags `false`. Neither package tsconfig duplicates `rootDir`/`outDir`.
  </done>

<task type="auto">
  <name>Task 2: Add placeholder entry points and prove the cold composite build</name>
  <files>packages/gherkin/src/index.ts, packages/vitest/src/index.ts</files>
  <action>
Both packages currently have no `src/`, which is why `tsc` raises
`TS18003: No inputs were found`. Create minimal, honest placeholder entry
points — no library logic (that is Phase 2+), but real exported values so
declaration emit is observable and the cross-package reference is exercised.

`packages/gherkin/src/index.ts`:
```ts
/**
 * Public entry point for `@effect-cucumber/gherkin`.
 *
 * Placeholder: this package has no behavior yet. Phase 2 replaces this file's
 * contents with `loadFeature` and the `ParsedFeature` types. The export below
 * exists so the package emits declarations and can be referenced by
 * `@effect-cucumber/vitest`.
 */
export const packageName = "@effect-cucumber/gherkin" as const

export type PackageName = typeof packageName
```

`packages/vitest/src/index.ts` — must import from `@effect-cucumber/gherkin`
**by package name** (not a relative path), so the composite project reference is
what resolves it. Use a namespace import, per AGENTS.md §3 and the
`namespaceImportPackages` setting:
```ts
import * as Gherkin from "@effect-cucumber/gherkin"

/**
 * Public entry point for `@effect-cucumber/vitest`.
 *
 * Placeholder: this package has no behavior yet. Phase 5 replaces this file's
 * contents with the `Feature` / `Scenario` / `Step` surface. The re-export
 * below exists so the cross-package project reference is exercised by the
 * build.
 */
export const packageName = "@effect-cucumber/vitest" as const

export const gherkinPackageName: Gherkin.PackageName = Gherkin.packageName
```

Note `erasableSyntaxOnly` and `verbatimModuleSyntax` are now on: no enums, no
parameter properties, no namespaces, and type-only imports must be marked
`import type` / inline `type`. The files above comply.

Then run a **cold** build and inspect the emitted artifacts.
