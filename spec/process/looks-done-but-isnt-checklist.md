# "Looks Done But Isn't" Checklist

The normative in-repo copy of the twenty-four-item checklist first written in this project's pitfalls
research. That research file is a `.planning/` artifact — unversioned as a contract, readable by no
gate under `scripts/`, and free to be edited without anything going red. This document is the
versioned form: the item text is transcribed from it rather than paraphrased, and the ids below are
what a gate cites.

## The ids

`P-01` through `P-24` are permanent, and they follow `AGENTS.md` §6's rules unchanged, the same rules
[`requirement-id-scheme.md`](./requirement-id-scheme.md) states for `BEH-EC-NNN`, `INV-EC-NNN`,
`ADR-EC-NNN` and `REQ-EC-NNN`:

- allocated **contiguously**, in the order the source list writes them, never out of a reserved
  future range;
- **never renumbered** and **never reused**;
- a withdrawn item is marked **Withdrawn** in place and keeps its number, because reuse would
  silently repoint every citation made before the withdrawal.

The order is the source list's own order. That is a one-way commitment: the ids are cited from two
gate scripts and from thirteen test titles, so renumbering afterwards touches all three.

## Every item is EXECUTED, never cited

The most feature-rich reading of "the checklist runs in full and passes" was chosen deliberately
(11-CONTEXT.md **D-03**): every item gets its own executing artifact, **even where an equivalent
assertion already exists elsewhere in this repository**. A checklist that points at scattered
existing tests is a citation list — you cannot run it, and an item whose cited test was deleted or
narrowed reads exactly like an item whose cited test still covers it. A checklist that is itself a
suite can be run, and can be counted.

The consequence is deliberate duplication, and it is enumerated rather than left to be discovered:
`packages/vitest/test/acceptance/pitfalls-checklist.test.ts` names, per item, the pre-existing
assertion it duplicates and why the duplication is intended. Do not "de-duplicate" that suite out of
existence.

Every artifact in the **Executed by** column is written as a plain path and never as a markdown link.
All three now exist, so the original reason — a link to a not-yet-written file fails this
repository's own relative-link check — has expired, and a second, now-primary one has replaced it:
**this column is machine-read.** `scripts/verify-pitfalls-checklist.sh` parses it and opens the file
it names. A markdown link would make the parsed value a link construct rather than a path, and the
cross-check would have to learn markdown to keep working. Plain paths, one per row.

`scripts/verify-pitfalls-checklist.sh` is what cross-checks this document against those artifacts: it
reads the ids from the table below and proves each one's named executor really carries it, so an item
that silently loses its executor fails `pnpm verify:pitfalls` rather than quietly becoming a smaller
pass count nobody is watching. That is a statement about what happens today, not a plan.

### An executor "carries" an id only in the ANCHORED form

The cross-check does **not** grep the executor for the bare id, and the reason is a measurement rather
than a preference. Plan 11-07 stripped `P-04 —` from a test's title and left the assertions intact;
a whole-file `grep -c 'P-04'` over
`packages/vitest/test/acceptance/pitfalls-checklist.test.ts` still returned **2**, satisfied by that
file's own header prose documenting the id. A cross-check written the obvious way would have been
green against a test that had lost its id — the fifth time this repository has hit the
count-your-own-prose shape. So the anchored forms are these, and they are load-bearing:

| Executor kind            | Anchored form                                                                                                                                                  |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| the in-process test file | the id preceded by a string literal's opening double quote **or** by a Gherkin `Scenario:` keyword, then a space, an em dash, a space, and an **ASCII letter** |
| a `scripts/verify-*.sh`  | a line **beginning** with `echo`, a double quote, the ✓ glyph, the id, a space, an em dash and a space — the assertion's own success line, never a comment     |

Each form is described rather than quoted, and the trailing space matters in both — a table cell
cannot carry one, and a document that "shows" the anchor is a document that would satisfy the anchor.
Read `scripts/verify-pitfalls-checklist.sh` for the regexes themselves.

Three details are not decoration. The `Scenario:` alternative exists because **P-12**'s two nodes are
Gherkin Scenario titles inside an inline Feature source rather than arguments to a test call. The
**trailing ASCII letter** exists because the in-process file's own header quotes the `P-04` anchor
while explaining this hazard and quotes the `P-12` anchor twice more — all three followed by
punctuation, none by a letter. And the script form is anchored at the START of a line because this
file, and every gate script, discusses ids in comments.

Both forms are things an executing artifact emits. Neither is satisfiable by describing an item.

## The rule that keeps this document honest

Three things may happen to an item. Nothing else may.

1. It may be marked **Withdrawn**, in place, keeping its number.
2. It may gain a **Note**, stating in full what changed and what the item is executed as instead.
3. Its **Executed by** may move to a different artifact, when the honest form of the item turns out to
   belong to a different kind of gate.

And three things may never happen to one:

- **It may never be deleted.** A checklist you can shorten when an item gets awkward measures your
  patience, not your software.
- **It may never be reworded to match what was convenient to assert.** Where the original wording is
  superseded or unbuildable, the wording STAYS and a Note is added beside it. P-10, P-13 and P-15 are
  the three rows where that has already happened, and each says so at length rather than reading as
  though it had always meant the smaller thing.
- **It may never be marked covered by citing a test elsewhere in the repository.** That is the whole
  of D-03, and it is why thirteen items are duplicated on purpose. An item's **Executed by** names an
  artifact that RUNS the item, never an artifact that happens to contain a similar assertion.
